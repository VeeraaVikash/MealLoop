# Requirements traceability matrix

Companion to [`PRD.md`](PRD.md) v0.2 (draft for team review, not owner-approved). One row per requirement. Dated 2026-10-23. Non-functional requirements are traced in [`NFR_TRACEABILITY.md`](NFR_TRACEABILITY.md).

**How to read it**

- *Source specification and screen family*: the repository document the requirement comes from, then the documented image or pack names of the screens (for example `K02_home_during_meal`). Nothing here is an invented Figma node or screen ID. A blank screen list means the behaviour is not drawn.
- *Planned backend module*: the module names in [`docs/backend/BACKEND_PROPOSAL.md`](backend/BACKEND_PROPOSAL.md). "to be decided" means the proposal does not yet assign an owner module.
- *Acceptance-test scenario*: one line; the full criteria are in the PRD.
- **Three separate states** are kept for every requirement. Nothing here claims more than the evidence shows:
  - **Foundation code exists**: Swift source exists on `feature/swiftui-foundation` (the file is named). This says nothing about whether it works.
  - **Verified on simulator or device**: only what is evidenced. The only evidence in the repository's records is that the owner reports the app was built and launched on the owner's Mac (owner-reported, with no build output kept). No unit-test result is recorded and `docs/FOUNDATION_VERIFICATION.md` does not exist, so no individual behaviour is evidenced and every row says *Not evidenced*.
  - **Production functionality**: the foundation runs on seeded demo data and its remote repository throws *Not implemented*, so no requirement has production functionality: every row says *Unimplemented*.
