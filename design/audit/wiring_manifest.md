# Wiring manifest · Final-fix F7 (2026-10-04)

All data is sample. This file lists every tappable element on every 393 pt frame of pages **07 Prototype & QA** (261 frames), **09 Mess Staff** (54) and **10 Admin** (163), and where it goes. It was made with `tools/wire7.js` (stored as `mealloop/wire7`) plus a status pass, after the F7 link fixes.

A tappable is anything with a link, or anything that looks tappable: Button, GlassButton, ListRow, SettingsRow, SearchResultRow, IntentChoice, ReasonPicker, pills, MenuDishTile, tiles with a chevron, tab-bar items, Back, Close, the avatar, Search, and any visible chevron. Controls under a sheet's scrim are background and are not listed. Children of a linked card are covered by the card.

## How to read a row

The brief asks for the columns frame, element, destination and status. About 3,500 elements would make that table unreadable, so it is folded to one row per frame (decision logged). Each element still carries its destination and status. The raw one-line-per-element output (frame \t element \t destination \t status) is stored in the file's plugin data (`mealloop/w7_*`) and is regenerated by `wire7.js`.

Columns: **frame | element → destination [status]**. One row per frame, with the elements in layer order.

| Status | Meaning |
|---|---|
| `→ frame` | linked |
| `Back ✓` | Back or Close → Back (returns where the user came from) |
| `Search ✓` | admin and student Search circle → Search (AD-8c · Search — Recent / Search · Empty) |
| `tab bar ✓` | all tab items are linked; on a tab root the current tab is not self-linked |
| `home cards ✓` | the 9 student Home cards (Entry QR, Special pass, Crowd, Follow-up, Impact, Method, Credits, Report a problem, Notifications), all linked as on Home · Afternoon |
| `(frame timer) → (after delay)` | Sending → Saved / Sent happens in place after a short delay |
| `in place (… variant change)` | an interactive component (DecisionActions, HeroActions) switches its own variant; no screen change |
| `[current tab]`, `[current view]`, `[current answer]` | the control shows where the user already is |
| `[in-place control]` | toggles, segments, steppers, reason pickers, option rows: they change the screen they sit on |
| `[display only]` | information rows, chips and tiles with no detail by design |
| `[disabled: …]` | dashed or outlined disabled control with a readable label (offline, cutoff passed, in progress) |
| `[phone call (no screen)]`, `[system settings (no screen)]` | leaves the app |
| `[state: …]` | a control on a state frame whose result is the same screen (Try again on Error) |
| `[destination absent: …]` | the screen it should open does not exist yet; listed in finalfix_report.md as a screen to build |
| `gallery → frame` | the student state gallery: tap the right half for the next state, the left half for the previous one |
